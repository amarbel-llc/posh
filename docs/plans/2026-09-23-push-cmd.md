# Push-cmd Implementation Plan

> **Done 2026-09-23:** all twelve tasks landed. Deleting the overlay (and
> renaming `$POSH_ESCAPE_CMD`) is the posh#213 cutover; the kernel cwd step on
> macOS is posh#214.

> **For Claude:** REQUIRED SUB-SKILL: Use eng:subagent-driven-development to implement this plan task-by-task.

**Goal:** *push-cmd* — run a command as a new anonymous session in the current
session's working directory and push the viewport onto it — replacing FDR
0008's escape-to-shell overlay and `posh fork`.

**Architecture:** Two entry points share one creation path. The CLI (`posh
start -- <cmd>` inside a session) already creates a session and re-homes the
viewport (posh#183); it gains nothing but documentation. The palette's *Push
shell* asks the session daemon (RFC 0016, deduplicated by token); the daemon
creates the session via `ensure_session` in the directory ADR 0008's cascade
chooses and re-homes the *requesting* viewport through the existing FDR 0012
`Tag::Switch`. `Event::Entered` pushes; the pushed session ending triggers
the existing default pop and its notice. The overlay stays as the palette's
fallback until the posh#213 cutover.

**Tech Stack:** Rust (`crates/posh`, `crates/posh-proto`), the RFC 0001
capability table, the session daemon's IPC.

**Rollback:** Palette push-cmd is gated on a daemon offer. A client that stops
advertising `CAP_PUSH_CMD` is never offered it and falls back to *Shell out*
(the unchanged overlay). The CLI path is pre-existing. `posh fork`'s removal
(Task 10) is the one irreversible user-facing change; land it last and
separately so it can be reverted alone.

**Records:** FDR 0020 (feature), RFC 0016 (wire), ADR 0008 (directory,
accepted). FDR 0020 and RFC 0016 stay `proposed` until the code lands; FDR
0008 flips to `superseded` in the commit that lands palette push-cmd.

---

## Settled decisions (do not re-litigate)

See FDR 0020 §Decisions. In short: replace, don't fold in; the daemon creates
the palette's session; anonymous with no marker; every pop announced; the
notice carries cause, numeric status and activity label; palette push-cmd only
end to end, overlay as fallback; `$POSH_ESCAPE_CMD` unchanged; one palette
entry; directory from ADR 0008's single cascade; lifetime independent of the
parent; `posh fork` removed.

## Facts the plan relies on (verified 2026-09-23)

- Unknown IPC tags and unknown capability entries are **skipped**
  (`FrameBuffer::next`, pinned by `unknown_tag_skipped`), so none of this
  needs a new IPC tag.
- Both bridges forward client capability entries to the daemon only through
  `relay::forwarded_client_caps` (`remote/relay.rs:230`), an explicit
  allow-list. **The relay must never gain ids 21/22** (ADR 0007). The M2
  bridge gets its own addition in `bridge_client_message`
  (`remote/server.rs:1136`).
- The daemon attaches `CAP_SESSION_KIND` once beside the first activity
  answer (`session/daemon.rs:389-401`). The offer copies that.
- `switch_route_target` (`session/daemon.rs:901`) **excludes** the requester,
  because in FDR 0012 the requester is a separate CLI process. A palette
  push-cmd's requester **is** the viewport: queue `Tag::Switch` on the
  requester's own connection.
- The CLI path exists: `posh start -- <cmd>` inside a session →
  `cmd_start_local` → `switch_in_place` (`session/client.rs:267`, posh#183).
  The new daemon forks from the CLI and inherits its cwd — ADR 0008 step 1.
- `ensure_session` (`session/daemon.rs:70`) binds, `double_fork`s, and runs
  `daemon_main`, which only `redirect_stdio_devnull`s. **Nothing closes
  inherited descriptors** in a session daemon; only the mux spawn does
  (`remote/mux.rs:1360`). A daemon forked from *inside a daemon* would inherit
  the parent's client sockets, listener and PTY master. Live check
  2026-09-23: a CLI-created daemon (`s-19`) held only its own four fds; no
  daemon created by a long-lived process was live to inspect.
- `Tag::Info` (`session/ipc.rs:295-352`) is a fixed core (`cwd` is the
  daemon's **start** directory, ≤256 bytes) followed by appended fields
  (activity label, then a kind byte), each tolerated absent by older
  readers. A provenance byte appends the same way.
- `session::next_autoid(cfg)` (`session/mod.rs:975`, `pub(crate)`).
- `posh fork`: `session::cmd_fork` (`session/mod.rs:912`), dispatched at
  `main.rs:320`, in usage at `main.rs:2099` and `:2992`, completions
  (`completions.rs:80, 216, 473, 483, 714`), `doc/posh.1.scd:268, 433`,
  `README.md:115`.
- Next free capability ids: **21, 22** (taken by Task 1).
- **Platform gaps (AGENTS.md):** any Linux-only code or test this plan adds
  goes behind `cfg(target_os = "linux")` like `pty::read_comm` (`pty.rs:88`),
  and its stub or gate carries a `macOS gap (posh#214):` comment naming what
  macOS would use; the same commit adds the site to posh#214. Tasks 4 and 5
  add one each.

```rust
/// RFC 0016 §2: the push-cmd offer, a request/answer pair like RFC 0013
/// §5.2's activity label. Client → server (empty): "I can push". Server →
/// client (empty), once, beside the first activity answer: "offered". Only a
/// local attach and the M2 bridge carry the client half — never the relay.
pub const CAP_PUSH_CMD: u8 = 21;

/// RFC 0016 §3: client → server, a push-cmd request: a nonzero big-endian
/// u64 token, then a reserved (unused) command field. Served once per token;
/// the token is seeded into the created session so a late repeat is ignored.
pub const CAP_PUSH_CMD_REQUEST: u8 = 22;

pub fn encode_push_cmd() -> Cap {
    Cap { id: CAP_PUSH_CMD, payload: Vec::new() }
}

pub fn encode_push_cmd_request(token: u64) -> Cap {
    Cap { id: CAP_PUSH_CMD_REQUEST, payload: token.to_be_bytes().to_vec() }
}

/// The token; `None` when shorter than 8 bytes or zero. A tail is ignored.
pub fn decode_push_cmd_request(payload: &[u8]) -> Option<u64> {
    let token = u64::from_be_bytes(payload.get(..8)?.try_into().ok()?);
    (token != 0).then_some(token)
}
```
